Penhoon UI همه چیز را — inboundها، کلاینت‌ها و تنظیمات — در یک پایگاه داده ذخیره می‌کند.
بک‌اند را هنگام نصب انتخاب می‌کنید؛ هر دو کاملاً پشتیبانی می‌شوند.

## SQLite (پیش‌فرض)

یک فایل واحد در مسیر `/etc/p-ui/p-ui.db`. بدون نیاز به هیچ راه‌اندازی، ایده‌آل برای
استقرارهای کوچک و متوسط. این پوشه با
[`PUI_DB_FOLDER`](/docs/reference/env-vars#database) قابل تنظیم است (در ویندوز به‌طور
پیش‌فرض کنار فایل اجرایی قرار می‌گیرد).

## PostgreSQL

برای تعداد بالای کلاینت‌ها یا راه‌اندازی‌های چندنودی توصیه می‌شود. نصب‌کننده می‌تواند
PostgreSQL را به‌صورت محلی برای شما نصب کند، یا یک DSN به سروری موجود را بپذیرد. در زمان
اجرا بک‌اند از طریق متغیرهای محیطی انتخاب می‌شود که نصب‌کننده آن‌ها را در فایل محیطیِ
سرویس، مخصوص توزیع شما، می‌نویسد — `/etc/default/p-ui` روی Debian/Ubuntu/Armbian،
`/etc/conf.d/p-ui` روی Arch/Manjaro/Parch/Alpine، و `/etc/sysconfig/p-ui` روی
میزبان‌های خانواده‌ی RHEL:

```bash title="/etc/default/p-ui (Debian/Ubuntu)"
PUI_DB_TYPE=postgres
PUI_DB_DSN=postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable
```

استخر اتصال را با `PUI_DB_MAX_OPEN_CONNS` و
`PUI_DB_MAX_IDLE_CONNS` تنظیم کنید.

### Docker

دستور `docker compose up -d` همچنان از SQLite استفاده می‌کند. برای اجرا با سرویس
PostgreSQL همراه، دو خط `PUI_DB_*` را در `docker-compose.yml` از حالت کامنت خارج کنید و
با این پروفایل اجرا کنید:

```bash
docker compose --profile postgres up -d
```

## مهاجرت از SQLite به PostgreSQL

ساده‌ترین راه، اسکریپت مدیریتی است: دستور `p-ui` را اجرا کنید، گزینه‌ی
**25) PostgreSQL Management** و سپس **2) Migrate SQLite → PostgreSQL** را انتخاب کنید.
این گزینه داده‌ها را کپی می‌کند، `PUI_DB_TYPE` و `PUI_DB_DSN` را در فایل محیطیِ مخصوص
توزیع شما می‌نویسد و پنل را برای شما مجدداً راه‌اندازی می‌کند.

برای مهاجرت دستی، مستقیماً باینری پنل را فراخوانی کنید — `migrate-db` زیردستورِ
`/usr/local/p-ui/p-ui` است، نه زیردستور اسکریپت مدیریتیِ `p-ui`:

```bash
systemctl stop p-ui
/usr/local/p-ui/p-ui migrate-db --dsn "postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable"
```

سپس `PUI_DB_TYPE` و `PUI_DB_DSN` را در فایل محیطیِ مخصوص توزیع خود (بالا را ببینید)
تنظیم کرده و سرویس را مجدداً راه‌اندازی کنید:

```bash
systemctl restart p-ui
```

<Callout type="info">
  فایل مبدأ SQLite دست‌نخورده باقی می‌ماند — آن را تنها پس از اینکه از کارکرد صحیح
  بک‌اند جدید مطمئن شدید، به‌صورت دستی حذف کنید.
</Callout>

## پشتیبان‌گیری

از هر بک‌اندی که استفاده می‌کنید، به‌طور منظم از آن پشتیبان بگیرید — به
[پشتیبان‌گیری و بازیابی](/docs/operations/backup-restore) مراجعه کنید.
