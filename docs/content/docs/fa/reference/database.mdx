‏Penhoon UI همه چیز را — inboundها، کلاینت‌ها و تنظیمات — در **PostgreSQL** ذخیره می‌کند.
این تنها بک‌اند پشتیبانی‌شده است و هنگام نصب چیزی برای انتخاب وجود ندارد.

## اتصال

نصب‌کننده یا PostgreSQL را از بسته‌های توزیع شما نصب می‌کند و یک کاربر و پایگاه‌دادهٔ
اختصاصی می‌سازد، یا DSN سروری را که از قبل دارید می‌پذیرد. در هر دو حالت رشتهٔ اتصال را در
فایل محیطی سرویس که systemd آن را می‌خواند، یعنی `/etc/default/p-ui`، می‌نویسد:

```bash title="/etc/default/p-ui"
PUI_DB_DSN=postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable
```

<Callout type="warn">
  تنظیم `PUI_DB_DSN` **الزامی** است. اگر تنظیم نشده باشد یا معتبر نباشد، پنل هنگام
  راه‌اندازی با خطایی متوقف می‌شود که نام همین متغیر و یک نمونه DSN را نشان می‌دهد — هرگز
  به یک فایل محلی برنمی‌گردد. پس از ویرایش این فایل، سرویس را ری‌استارت کنید:
  `systemctl restart p-ui`.
</Callout>

استخر اتصال را با `PUI_DB_MAX_OPEN_CONNS` و `PUI_DB_MAX_IDLE_CONNS` تنظیم کنید. نگاه کنید
به [متغیرهای محیطی](/docs/reference/env-vars).

## مدیریت PostgreSQL

دستور `p-ui` را اجرا کنید و بخش **PostgreSQL Management** را باز کنید تا سرور را نصب
کنید، وضعیت کلاستر را ببینید، آن را شروع/متوقف/ری‌استارت کنید، اجرای خودکار در بوت را فعال
کنید، لاگ آن را بخوانید یا ابزارهای کلاینت را نصب کنید.

## ابزارهای کلاینت

‏`pg_dump` و `pg_restore` از بستهٔ `postgresql-client` می‌آیند و پشتوانهٔ دکمه‌های
پشتیبان‌گیری و بازگردانی در پنل هستند. نصب‌کننده آن‌ها را برایتان اضافه می‌کند؛ اگر موجود
نباشند، پنل به‌جای ساختن یک پشتیبانِ ناقص، همین را گزارش می‌دهد.

فایل پشتیبانی که با نسخه‌ای **جدیدتر** از PostgreSQL ساخته شده باشد، برای `pg_restore`
محلی قابل خواندن نیست. خطای پنل نسخهٔ اصلی مورد نیاز را نام می‌برد؛ کلاینت متناسب را
این‌گونه نصب کنید:

```bash
p-ui pgclient 17
```

## پشتیبان‌گیری

به‌طور منظم پشتیبان بگیرید — به
[پشتیبان‌گیری و بازیابی](/docs/operations/backup-restore) مراجعه کنید.
