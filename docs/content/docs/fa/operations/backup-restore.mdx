تمام پیکربندی شما — ورودی‌ها، کلاینت‌ها و تنظیمات — در پایگاه‌داده‌ی PostgreSQL پنل قرار
دارد. مرتب از آن پشتیبان بگیرید تا بتوانید بازیابی یا مهاجرت کنید.

## از چه چیزی پشتیبان بگیریم

- **پایگاه‌داده** — همان پایگاه‌داده‌ی PostgreSQL که در
  [`PUI_DB_DSN`](/docs/reference/env-vars) نام برده شده است.
- **گواهی‌ها** — هر چیزی که زیر `/root/cert/` (یا هر جایی که گواهی‌های TLS را نگه می‌دارید)
  قرار دارد.

## از داخل پنل

دکمه‌ی **Back Up** در صفحه‌ی نمای کلی، یک آرشیو با قالب custom از `pg_dump` (فایل `.dump`)
تحویل می‌دهد که نامش بر اساس آدرس سرور و تاریخ روز ساخته می‌شود. دکمه‌ی **Import** همان
فایل را برمی‌گرداند: پنل ابتدا بررسی می‌کند که `pg_restore` محلی بتواند فایل را بخواند،
سپس Xray را متوقف می‌کند، پایگاه‌داده را بازیابی می‌کند و دوباره آن را بالا می‌آورد. این
بازیابی مخرب است — محتوای فعلی پایگاه‌داده را جایگزین می‌کند.

<Callout type="warn">
  هر دو دکمه به `pg_dump` و `pg_restore` روی سرور نیاز دارند (بسته‌ی
  `postgresql-client`). نصب‌کننده آن‌ها را اضافه می‌کند؛ اگر موجود نباشند، پنل به‌جای
  نوشتن یک پشتیبانِ ناقص همین را گزارش می‌دهد.
</Callout>

## از خط فرمان

همان پشتیبان، به‌صورت دستی:

```bash title="back up"
pg_dump --format=custom --no-owner --no-privileges \
  "postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable" \
  > /root/p-ui-backup-$(date +%F).dump
```

```bash title="restore"
p-ui stop
pg_restore --clean --if-exists --no-owner --no-privileges --single-transaction \
  --dbname "postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable" \
  /root/p-ui-backup-2026-01-31.dump
p-ui start
```

## پشتیبان‌گیری با Telegram

اگر [ربات Telegram](/docs/operations/telegram-bot) را پیکربندی کرده‌اید، گزینه‌ی
**`tgBotBackup`** را فعال کنید تا یک نسخه‌ی پشتیبان به گزارش دوره‌ای ضمیمه شود (بر اساس
زمان‌بندی `tgRunTime`، به‌صورت پیش‌فرض روزانه). ربات هم **دامپ پایگاه‌داده** و هم
**`config.json` مربوط به Xray** را به چت ادمین شما می‌فرستد، بنابراین همیشه یک نسخه‌ی خارج
از سرور در اختیار دارید. ادمین‌ها همچنین می‌توانند به‌صورت درخواستی از منوی ربات یک نسخه‌ی
پشتیبان بخواهند.

## سازگاری نسخه‌ها

فایل پشتیبانی که با نسخه‌ای جدیدتر از PostgreSQL ساخته شده باشد، برای `pg_restore` سرور
مقصد قابل خواندن نیست — پنل پیش از دست‌زدن به چیزی آن را رد می‌کند و نسخه‌ی اصلی مورد نیاز
را نام می‌برد. کلاینت متناسب را نصب کنید و دوباره تلاش کنید:

```bash
p-ui pgclient 17
```

<Callout type="warn">
  هر وقت ممکن است، یک نسخه‌ی پشتیبان را روی **همان نسخه‌ی اصلی (major)** پنلی که از آن
  گرفته شده بازیابی کنید. در ارتقاهای میان‌نسخه‌ای اصلی، به‌جای تحمیل یک شِمای قدیمی،
  بگذارید پنل مهاجرت‌های خود را اجرا کند.
</Callout>

<Callout type="info">
  از هر روشی که استفاده می‌کنید، نسخه‌های پشتیبان را **خارج از سرور** نگه دارید و هرازگاهی
  یک بازیابی را آزمایش کنید — یک نسخه‌ی پشتیبانِ آزمایش‌نشده، پشتیبان به‌حساب نمی‌آید.
</Callout>
