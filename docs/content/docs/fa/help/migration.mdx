## بین سرورها

انتقال به سرور جدید در واقع یک جابه‌جایی پایگاه‌داده است:

<Steps>

<Step>
### از سرور قدیمی نسخه پشتیبان بگیرید

با دکمهٔ **Back Up** در پنل (یا با `pg_dump`) یک دامپ از پایگاه‌داده بگیرید و از
گواهی‌نامه‌های خود کپی تهیه کنید.
[پشتیبان‌گیری و بازیابی](/docs/operations/backup-restore) را ببینید.
</Step>

<Step>
### Penhoon UI را روی سرور جدید نصب کنید

از یک نسخهٔ سازگار استفاده کنید و بگذارید نصب‌کننده، PostgreSQL را همان‌جا راه‌اندازی کند.
[نصب](/docs/guide/installation) را ببینید.
</Step>

<Step>
### پایگاه‌داده را بازیابی کنید

دامپ را از داخل پنل وارد کنید (یا با `pg_restore` بازگردانید)، گواهی‌نامه‌ها را بازیابی کرده و پنل را دوباره راه‌اندازی کنید. هر تنظیم وابسته به IP یا دامنه را به‌روزرسانی کنید.
</Step>

</Steps>

## بین نسخه‌های Penhoon UI

ارتقا معمولاً تنها به اجرای دوبارهٔ نصب‌کننده یا `p-ui update` خلاصه می‌شود — پنل خودش
شِمای پایگاه‌داده‌اش را مهاجرت می‌دهد. هنگام تغییر بین نسخه‌های **اصلی**،
ابتدا [یادداشت‌های انتشار](https://github.com/Arman2122/p-ui/releases)
را بخوانید و یک نسخهٔ پشتیبان تهیه کنید.

## از x-ui اصلی

وارد کردن مستقیم پایگاه‌دادهٔ یک پنل قدیمی x-ui به Penhoon UI **پشتیبانی نمی‌شود** —
چون ساختار schema آن‌ها متفاوت است. Penhoon UI را از نو نصب کنید و inboundها/کلاینت‌ها را
دوباره بسازید و در همین حین لینک‌های اشتراک‌گذاری را از پنل قدیمی خروجی بگیرید.

<Callout type="warn">
  پیش از هر مهاجرتی همیشه یک نسخهٔ پشتیبان تهیه کنید و سرور قدیمی را تا زمانی که
  از درستی عملکرد سرور جدید مطمئن نشده‌اید، روشن نگه دارید.
</Callout>
