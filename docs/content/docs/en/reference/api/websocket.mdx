## Messages

Every frame is the same JSON envelope: `type` selects one of these payload shapes, `payload` carries it, and `time` is the send time in Unix milliseconds.

### `type: status`

Server health snapshot pushed every 2 seconds. The payload contains CPU, memory, swap, disk, network IO, load, and Xray state — same shape as <code>GET /panel/api/server/status</code>.

```json
{
  "type": "status",
  "payload": { "cpu": 12.5, "mem": { "current": 2147483648, "total": 8589934592 }, "xray": { "state": "running" } },
  "time": 1725000000000
}
```

### `type: xray_state`

Xray process state change. Fired when Xray starts, stops, or encounters an error; <code>state</code> is <code>running</code>, <code>stop</code> or <code>error</code>, and <code>errorMsg</code> carries the reason when it is <code>error</code>.

```json
{
  "type": "xray_state",
  "payload": { "state": "running", "errorMsg": "" },
  "time": 1725000000000
}
```

### `type: notification`

In-panel toast notification. Fired on Xray stop/restart, DB import, panel restart, etc. <code>level</code> is <code>success</code>, <code>info</code>, <code>warning</code> or <code>error</code>.

```json
{
  "type": "notification",
  "payload": { "title": "Xray service restarted", "message": "Xray service has been restarted successfully", "level": "success" },
  "time": 1725000000000
}
```

### `type: invalidate`

Instructs the UI to re-fetch a resource. Fired when another admin session modifies data (e.g. toggling inbound enable). The payload names the message type whose cached data is stale: <code>inbounds</code>, <code>outbounds</code>, <code>nodes</code> or <code>clients</code>.

```json
{
  "type": "invalidate",
  "payload": { "type": "inbounds" },
  "time": 1725000000000
}
```
