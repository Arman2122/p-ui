Penhoon UI stores everything — inbounds, clients, settings — in **PostgreSQL**. It is the
only supported backend; there is nothing to choose at install time.

## Connecting

The installer either installs PostgreSQL from your distribution's packages and
creates a dedicated role and database, or takes a DSN for a server you already
run. Either way it writes the connection string to the service environment file
that systemd loads, `/etc/default/p-ui`:

```bash title="/etc/default/p-ui"
PUI_DB_DSN=postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable
```

<Callout type="warn">
  `PUI_DB_DSN` is **required**. If it is unset or unparseable the panel stops at
  startup with an error naming the variable and showing an example DSN — it never
  falls back to a local file. After editing the file, restart:
  `systemctl restart p-ui`.
</Callout>

Tune the connection pool with `PUI_DB_MAX_OPEN_CONNS` and
`PUI_DB_MAX_IDLE_CONNS`. See [Environment variables](/docs/reference/env-vars).

## Managing PostgreSQL

Run `p-ui` and open **PostgreSQL Management** to install the server, check
cluster status, start/stop/restart it, enable it on boot, read its log, or
install the client tools.

## Client tools

`pg_dump` and `pg_restore` come from the `postgresql-client` package and back the
panel's Back Up / Import buttons. The installer adds them for you; if they are
missing, the panel says so instead of producing a broken backup.

A dump written by a **newer** PostgreSQL than the local `pg_restore` understands
cannot be imported. The panel's error names the major version it needs — install
a matching client with:

```bash
p-ui pgclient 17
```
