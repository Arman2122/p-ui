After a script install, the `p-ui` command is your control center. Run it with
no arguments for the interactive menu, or pass a subcommand for a one-shot action.

```bash
p-ui
```

## The `p-ui` management menu

The menu (items `0`–`28`) shows the panel/Xray status at the top, then:

| #     | Item                                   | What it does                                              |
| ----- | -------------------------------------- | --------------------------------------------------------- |
| 1     | Install                                | (Re)install from the remote script                        |
| 2     | Update                                 | Update to the latest **stable** release                   |
| 3     | Update to Dev Channel (latest commit)  | Update to the rolling `dev-latest` build                  |
| 4     | Update Menu                            | Update just the `p-ui` menu script                        |
| 5     | Legacy Version                         | Install a specific older version (prompts for a tag)      |
| 6     | Uninstall                              | Remove Penhoon UI (see below)                             |
| 7     | Reset Username & Password              | Set new credentials; optionally disable 2FA               |
| 8     | Reset Web Base Path                    | Randomize the web base path                               |
| 9     | Reset Settings                         | Reset panel settings (your account is preserved)          |
| 10    | Change Port                            | Change the panel port                                     |
| 11    | View Current Settings                  | Show username, port, web base path, cert paths            |
| 12–14 | Start / Stop / Restart                 | Control the panel service                                 |
| 15    | Restart Xray                           | Reload only Xray-core                                     |
| 16    | Check Status                           | Service status                                            |
| 17    | Logs Management                        | View debug logs / clear logs                              |
| 18–19 | Enable / Disable Autostart             | Toggle start-on-boot                                      |
| 20    | SSL Certificate Management             | Let's Encrypt (domain or IP), custom paths, renew/revoke  |
| 21    | Cloudflare SSL Certificate             | DNS-01 wildcard cert via Cloudflare                       |
| 22    | IP Limit Management                    | Fail2ban-based per-client IP limits                       |
| 23    | Firewall Management                    | `ufw` install and port rules                              |
| 24    | SSH Port Forwarding Management         | Bind the panel to localhost and tunnel over SSH           |
| 25    | PostgreSQL Management                  | Install, inspect and control the PostgreSQL server        |
| 26    | Enable BBR                             | Toggle the BBR congestion-control sysctl                  |
| 27    | Update Geo Files                       | Update geoip/geosite data (Loyalsoldier, IR, RU)          |
| 28    | Speedtest by Ookla                     | Run an Ookla speed test                                   |
| 0     | Exit                                   | —                                                         |

Some of these have their own pages: [SSL certificates](/docs/config/ssl-certificates)
(items 20–21), [Security](/docs/operations/security) (IP limits, firewall),
[Reverse proxy](/docs/operations/reverse-proxy) and [Panel settings](/docs/config/panel)
(TLS), and [Database](/docs/reference/database) (PostgreSQL).

## CLI subcommands

For scripts and quick actions, `p-ui` also takes a subcommand directly:

| Command                    | Action                                              |
| -------------------------- | --------------------------------------------------- |
| `p-ui start` / `stop` / `restart` | Control the service                          |
| `p-ui restart-xray`        | Reload only Xray-core                               |
| `p-ui status`              | Show status                                         |
| `p-ui settings`            | Show current settings                               |
| `p-ui enable` / `disable`  | Toggle autostart on boot                            |
| `p-ui log`                 | Tail the debug log                                  |
| `p-ui banlog`              | Show Fail2ban ban log                               |
| `p-ui update`              | Update to the latest stable release                 |
| `p-ui update-dev`          | Update to the rolling `dev-latest` build            |
| `p-ui legacy`              | Install a specific older version (prompts)          |
| `p-ui update-all-geofiles` | Update all geo files, restart if changed            |
| `p-ui pgclient [ver]`      | Install/upgrade the PostgreSQL client tools (`pg_dump`/`pg_restore`) |
| `p-ui install` / `uninstall` | Install / uninstall                               |

Run `p-ui` with an unknown subcommand to print this list from the script itself.

## Updating

- **Stable:** menu option **2** or `p-ui update`. Re-running the install script
  also updates in place.
- **Dev channel:** menu option **3** or `p-ui update-dev` — the rolling
  `dev-latest` per-commit build (not a stable release).
- **A specific older version:** menu option **5** (Legacy Version).

Updating preserves your database and settings. Take a
[backup](/docs/operations/backup-restore) before a major-version jump.

### What an update trusts

The updater script is fetched **from the release being installed**, never from
the repository's `main` branch, and every release archive is checked against the
`.sha256` published beside it before anything is extracted. An archive whose
digest cannot be fetched or does not match is refused and deleted.

Releases before v1.5.2 publish no digest, so installing one of those — a pinned
`install.sh v1.5.0`, or `PUI_UPDATE_TAG` set to an old tag — is refused too.
`PUI_SKIP_CHECKSUM=1` is the explicit escape for that case. This does not
protect against a compromised release account, which can publish its own
digests.

### What an update leaves behind

An update extracts the new release beside the live tree and runs its binary
once before the panel is stopped, so a broken archive leaves the running panel
untouched. The old binaries are set aside rather than deleted; if the new panel
is not active within 15 seconds they are put back and started again, and the
script points you at `journalctl -u p-ui -n 50`. This protects updates *to* a
release that ships this behaviour, since `p-ui update` runs the updater
published with the release being installed.

## Uninstalling

Menu option **6** or `p-ui uninstall`. It stops and disables the service, removes
the service unit, and deletes `/etc/p-ui/` and the install folder. If the panel
used a locally-installed PostgreSQL, it offers to purge that too (a separate,
irreversible confirmation).

<Callout type="warn">
  Purging the local PostgreSQL destroys the panel database and your entire
  configuration. [Back up](/docs/operations/backup-restore) first if you might
  need it.
</Callout>
