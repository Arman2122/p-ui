A proxy panel is a high-value target. A few layers of hardening go a long way.

## Panel hardening

- Strong, unique credentials and **two-factor auth** (TOTP).
- A non-default panel port and a long, random web base path.
- TLS on the panel (directly or via a [reverse proxy](/docs/operations/reverse-proxy)).
- The built-in **login limiter** blocks an IP/username after 5 failed attempts
  in 5 minutes (for 15 minutes), and the panel can route its own egress through
  an outbound.

See [First login](/docs/guide/first-login) for the full checklist.

## IP limits (device cap)

Set an **IP limit** per client (see [Clients](/docs/config/clients)) to cap the
number of simultaneous source addresses. How a device over the cap is dealt with
depends on the core serving the inbound:

- **SSH, OpenVPN, OpenConnect** refuse the extra device at their own login and cut
  one already connected. No firewall is involved.
- **sing-box** (TUIC, AnyTLS) cuts the connection and the panel drops the address.
- **Xray** (VLESS, VMess, Trojan, Shadowsocks, Hysteria, WireGuard) and **kernel
  WireGuard** cannot end one session, so the panel drops the address.

A drop is a row in the panel's database projected onto the panel's **own
nftables table** (`inet p-ui-ipl`): the address is dropped only on the ports of
the inbounds the client is on, never on the whole host, for the **ban duration**
setting (30 minutes by default). The kernel releases it on time even if the
panel is down. A client served by a node is decided on the master, from what the
node reported, and the ban is pushed to that node.

Manage it under **Settings → Device cap** (duration, what to do with an address
another client under its own cap shares, the list of active bans with release),
from the client's address log, or from the shell:

```bash
p-ui ban                                  # list active bans
p-ui ban -add 203.0.113.7 -minutes 60     # ban an address on every inbound
p-ui ban -release 203.0.113.7             # release it
p-ui banlog                               # bans and the ban log
```

Set `PUI_IP_LIMIT_BANS=false` to record bans without dropping anything (the old
name `PUI_ENABLE_FAIL2BAN` is still read). Enable the **Clients → device limit**
notification to be told of every cut and ban; a client with a Telegram id is told
too.

<Callout type="warn">
  **Upgrading from a release that used Fail2ban?** The installer and updater
  remove the `p-ui-ipl` jail (its files under `/etc/fail2ban/jail.d/`,
  `filter.d/` and `action.d/`) so it stops banning every port beside the
  panel's own table; `p-ui` menu **22** has the same entry. Fail2ban itself is
  left installed for anything else you use it for.
</Callout>

## Network tuning (BBR)

The `p-ui` menu (**26 — Enable BBR**) toggles Google's BBR congestion control
(`net.ipv4.tcp_congestion_control = bbr`, `net.core.default_qdisc = fq`), which
often improves throughput on congested links.

## Keep current

Update Penhoon UI and Xray-core regularly — security fixes land in new releases. Watch
the [releases page](https://github.com/Arman2122/p-ui/releases) and see
[Update & uninstall](/docs/guide/update-uninstall).
