Your entire configuration — inbounds, clients, settings — lives in the panel's
PostgreSQL database. Back it up regularly so you can recover or migrate.

## What to back up

- **The database** — the PostgreSQL database named in
  [`PUI_DB_DSN`](/docs/reference/env-vars#database).
- **Certificates** — anything under `/root/cert/` (or wherever you store TLS
  certs).

## From the panel

The overview page's **Back Up** button streams a `pg_dump` custom-format archive
(`.dump`), named after the server and the current date. **Import** takes that
file back: the panel checks that the local `pg_restore` can read it, stops Xray,
restores into the database and restarts. The restore is destructive — it replaces
the current contents of the database.

<Callout type="warn">
  Both buttons need `pg_dump` / `pg_restore` on the server (the
  `postgresql-client` package). The installer adds them; if they are missing the
  panel reports it instead of writing a broken backup.
</Callout>

## From the command line

The same dump, taken by hand:

```bash title="back up"
pg_dump --format=custom --no-owner --no-privileges \
  "postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable" \
  > /root/p-ui-backup-$(date +%F).dump
```

```bash title="restore"
p-ui stop
pg_restore --clean --if-exists --no-owner --no-privileges --single-transaction \
  --dbname "postgres://pui:password@127.0.0.1:5432/pui?sslmode=disable" \
  /root/p-ui-backup-2026-01-31.dump
p-ui start
```

## Telegram backup

If you've configured the [Telegram bot](/docs/operations/telegram-bot), enable
**`tgBotBackup`** to attach a backup to the periodic report (on the `tgRunTime`
schedule, default daily). The bot sends both the **database dump** and the **Xray
`config.json`** to your admin chat, so you always have an off-server copy. Admins
can also request a backup on demand from the bot's menu.

## Version compatibility

A dump written by a newer PostgreSQL than the target server's `pg_restore`
understands cannot be imported — the panel refuses it before touching anything
and names the major version it needs. Install a matching client and retry:

```bash
p-ui pgclient 17
```

<Callout type="warn">
  Restore a backup onto the **same major version** of the panel it came from when
  possible. Across major upgrades, let the panel run its migrations rather than
  forcing an old schema.
</Callout>

<Callout type="info">
  Whatever method you use, store backups **off the server** and test a restore
  occasionally — an untested backup isn't a backup.
</Callout>
