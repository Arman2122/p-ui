A **client** is a single user, identified by a unique **email**. In the current
panel, clients are first-class records that can be attached to **multiple
inbounds** at once, with per-client traffic accounting.

## Client fields

| Field          | Applies to            | Meaning                                                            |
| -------------- | --------------------- | ------------------------------------------------------------------ |
| **Email**      | all                   | Unique identifier used for accounting and lookups.                 |
| **ID (UUID)**  | VLESS, VMess          | The client credential.                                             |
| **Password**   | Trojan, Shadowsocks   | The client credential.                                             |
| **Auth**       | Hysteria2             | The client credential.                                             |
| **Flow**       | VLESS                 | XTLS flow, e.g. `xtls-rprx-vision`.                                |
| **Limit IP**   | all                   | Max simultaneous source IPs (refused at login, cut, or dropped on the panel's firewall). |
| **Total (GB)** | all                   | Traffic quota; the client is disabled when exhausted.              |
| **Expiry**     | all                   | Date after which the client stops working.                        |
| **Reset**      | all                   | Auto-renew **after expiry**: days to extend by. Needs an Expiry.   |
| **Telegram ID**| all                   | Links the client to a Telegram user for self-service/notifications.|
| **Sub ID**     | all                   | Subscription identifier grouping this client's links.             |
| **Group**      | all                   | Optional client group for organization and bulk filtering.        |
| **Comment**    | all                   | Free-text note.                                                   |

<Callout type="info">
  Reaching the **traffic** or **expiry** limit disables the client. The panel can
  restart local Xray to end live connections after automatic disable, manual
  disable or deletion (`restartXrayOnClientDisable`, on by default). This setting
  applies to Xray; other cores use their own client-removal capabilities.
</Callout>

## Limits and IP control

- **Traffic / expiry** caps disable the client when hit.
- **Reset** renews a client *when its expiry date passes*: the deadline moves
  forward by that many days and the traffic counters go back to zero. It does
  nothing on its own — a client with a Reset period but **no Expiry date never
  renews**, because there is no deadline to move. Exhausting the traffic quota
  does not trigger it either; only the expiry date does. The field is labelled
  "Auto Renew (days)" in the panel.
- **Limit IP** caps simultaneous source IPs. Enforcement is the core's own login refusal or the panel's firewall table —
  see [Security](/docs/operations/security). You can view a client's recent IPs
  and clear them from the client's actions.
- **Online status** and **last-online** times are tracked per client (and per
  node in multi-node setups). A disabled client's status also says why: quota
  used up, expired, or switched off by hand.

## Share links and external links

Every client has share links and a QR code for its inbounds, plus a combined
[subscription](/docs/config/subscription). You can also attach **external
links** to a client — extra `vless://`, `vmess://`, `trojan://`, `ss://`,
`hysteria2://`, or `wireguard://` links, or a remote subscription URL — so they
appear alongside the panel-generated ones in the client's subscription. They
travel with the client through export and import.

A client on more than one WireGuard-family inbound (WireGuard, kernel WireGuard,
AmneziaWG) gets a picker above its config in the info and QR dialogs; the
config text, the QR code and the `.conf` download follow the chosen inbound.

To inspect exactly what a link contains, paste it into the
[share-link inspector](/docs/config/share-links).

## Bulk actions

For managing many clients at once, the panel supports bulk **create, enable,
disable, delete, attach/detach** (to inbounds), **reset traffic**, and
**adjust** (add days / add bytes in ADD mode, or make a value exactly this in
SET mode, plus a flow change), **set** (exact values for the IP limit, quota,
expiry, auto-renew, flow, group, speed plan, Telegram id and comment, each row
kept, set or cleared), **move** between inbounds (every client is attached
to the targets before it is detached from the sources), **clear IPs**,
**export selected** and **copy links** (every share link of the selection, one
per line) and **rotate credentials** (a fresh UUID, password, key or secret per
protocol, optionally a new subscription id: every link the selection was handed
stops working at once). The delete confirmation can keep the traffic history,
so a client re-created with the same email continues its counters. The selection is not limited to the page on
screen: once a whole page is selected, **Select all N matching** turns the
selection into the filter itself and the server resolves every matching
client. After any bulk action that skipped or failed a client, a drawer lists
each such row with its reason and lets you copy the failed emails or retry
exactly those. Maintenance actions also let you delete **depleted** clients
(quota/expiry exhausted) and **orphaned** clients (not attached to any
inbound).

<Callout type="warn">
  A client's share link contains its credential. Treat links and QR codes like
  passwords, and rotate the credential if one leaks.
</Callout>
