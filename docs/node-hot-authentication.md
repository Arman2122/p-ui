# Headless hot authentication

The saved stream adapters implement changes to one client's credentials or placement while retaining unrelated clients' listeners and authentication records. SSH and MTProto retain their earlier scoped qualification. Xray and sing-box now have immutable authentication bindings and hot-update fixtures, with the evidence and remaining gates distinguished below. A listener, transport, routing, or host-key change can still require a restart.

## Immutable identity proof

Each worker configuration contains the stable client ID, credential generation, placement ID and revision, inbound instance ID, and rendered inbound tag. The admission broker creates a distinct proof object for that exact descriptor. An adapter captures the object alongside the password or secret used to authenticate; it never looks up a replacement generation by username after authentication.

Preparing a configuration preserves the exact objects for unchanged descriptors and permanently retires changed or removed objects. New candidates remain unavailable until the backend succeeds and the worker persists its applied configuration. A failed or superseded candidate cannot reactivate an earlier proof, including a remove/re-add with identical descriptor values. While configuration application is pending, new activation requests are refused; existing unchanged funded clients retain their static proof and continue under their existing governor accounts.

An activation receipt still grants no forwarding authority. A later attempt needs both a current credential proof and a separately committed governor grant. Unknown or incorrect credentials produce no activation request.

Funded traffic also needs the captured proof. Existing quota accounts are retained through hot changes; an adapter cannot use an old authenticated object with a replacement client's account, even when a login name or raw credential is reused. New records are registered before publication and remain unusable until their admission proof commits. Retiring a record cancels its governed forwarding paths. A protocol carrier that remains physically connected still holds its original authentication handle and cannot adopt a new proof for later streams.

## Adapter boundaries

- **SSH:** each immutable credential record owns a random registration token and its proof. Rekeying or replacing the proof permanently revokes that record and closes its existing transports. After the SSH password callback succeeds, transport registration rechecks the exact token under the server lock. An old password callback paused across a rekey cannot register using the replacement record. Unchanged records and TCP/UDPGW carriers survive.
- **MTProto:** the maintained `mtg-proxy v1.9.0` patch attaches the proof to the same immutable snapshot that supplied the authenticated secret. Live registration checks the captured key against the currently published key under the connection registry lock and checks the captured proof. The governor receives that captured proof, including through WEB's in-process DD backend. Only changed subjects are disconnected; another client's EE, DD, and HTTPS WEB streams remain connected. Keys duplicated across client identities are rejected even when their hostnames differ. The matched key is copied so one old stream does not retain a complete old secret array.
- **Xray:** the enforcement registry binds the actual authenticated `MemoryUser` pointer to the canonical client ID, inbound and proof. It checks that binding at dispatch and at governed buffer admission, including for already-funded accounts. Unchanged user objects survive credential-only configuration updates; changed objects and their governed links retire. VLESS, VMess, Trojan, Shadowsocks AEAD and Hysteria use their user-management interfaces. HTTP/mixed use a shared synchronized store with immutable password/user records, exact-case usernames and mandatory authentication after the last account is removed. Hysteria's UUID route-byte clone carries its captured original user pointer.
- **Shadowsocks 2022:** the implementation replaces mutable user indexes with authenticated pointers and publishes the dependency's identity/key/cipher maps as one snapshot. An explicitly empty client array remains a multi-user authentication configuration. Marker-7 Linux coverage includes hot TCP/UDP traffic, actual inbound processing paused after authentication, failed-publication atomicity and concurrent fresh authentication during hot updates. The paused-pointer negative control reproduces the failure when its safeguard is removed.
- **sing-box TUIC and AnyTLS:** carriers retain immutable `TUICUser` or AnyTLS user handles. The tracker resolves those exact handles to proofs, retains unchanged handles and rejects retired handles on later streams. TUIC publishes its user/password maps together under synchronization; AnyTLS publishes immutable password-hash/user records under synchronization. Cached stream prefixes are transferred to owned bytes before governed copying so selective closure does not race the upstream cached-buffer reader. A separate pinned AnyTLS patch synchronizes stream terminal-error publication.
- **Shutdown:** SSH waits for its keepalive task; MTProto's direct Telegram dial receives the retiring stream's cancellation context. Xray's stream bridge interrupts the raw transport and joins copies before releasing buffered protocol state, propagates link closure and preserves half-close behavior. These lifecycle changes do not issue replacement authority.

## Native password authentication candidate

OpenVPN and ocserv now have candidate credential-bound admission plumbing. Their immutable authentication records capture the worker proof using the rendered inbound tag and canonical client ID. Correct credentials with unavailable authority can request activation outside authentication locks; the original attempt remains denied even when a receipt and a grant arrive while it waits. OpenVPN distinguishes unavailable authorization in its management response. RADIUS separately records successful credential verification, so this authorization denial does not invoke the failed-password callback. Unknown or wrong credentials never receive that classification.

Internal native compilation can represent authentication-only OpenVPN/ocserv clients with exact descriptor membership while creating forwarding assignments only for actual grants. WireGuard and AmneziaWG still require grants. Daemon startup captures proofs before enabling authentication; changed proof objects trigger replacement even when a failed apply retries identical descriptor values. Unchanged proof objects survive grant-only changes. OpenVPN reauthentication and establishment check the captured credential record; ocserv connect hooks also check the process-bound proof and retain their existing generation and worker-ownership checks.

These changes do not qualify native first-use publication. Public native admission support remains disabled; a same-base authority receiver candidate is now saved but has not passed Linux traffic qualification. Existing grant-only native configurations retain their funded path. Changes to native configuration or credential proof scope still restart the native process group; preservation of unrelated live daemon sessions through those changes and old ocserv cookie invalidation remain Linux qualification requirements.

Local pure-Go management, broker and configuration tests and an actual localhost RADIUS packet test pass. Portable race suites pass for OpenVPN (1.866 seconds), ocserv (2.651), native configuration (2.151), RADIUS (2.207), the admission broker (1.835), and the node compiler (2.089). Eight controls in `tools/nodekernel/native-admission-negative.py` reproduce retired-proof, receipt-promotion, failure-classification and descriptor/binding regressions; local evidence is retained under `scratchpad/node-v2/native-admission-negative-8f1l7gm3/` and `native-admission-*.log`.

The Linux native executable and touched packages cross-compile successfully, and scoped lint reports zero issues in Windows and Linux contexts. Cross-compilation is compilation evidence only. Actual pinned-daemon, kernel, service-sandbox and first-use UX qualification remain pending. OpenVPN and OpenConnect must eventually complete pending first-use without misleading wrong-password behavior or requiring manual reconnection; no asynchronous daemon authentication capability is assumed by this candidate.

## Native authority receiver candidate

The native authority candidate implements `worker.AuthorityBackend` behind the closed worker, agent and master capability gates. It accepts only current configured password-client proofs, retains static selector templates and adds ocserv selectors only from existing verified bindings. WireGuard/AmneziaWG first-use is not inferred from traffic or addresses. Native journal transitions persist a complete pending policy before kernel changes; ordinary reconciliation, credit refill, selector changes and network rebinding cannot bypass that pending state. Applied grants refresh daemon authentication caches without restarting them. Unqualified directional rate-mode changes are refused explicitly.

The Linux amendment path retains the live lease ID, class, reservation, deadline and nft quota/counter objects, purges selected queued packets, and changes an existing HTB class in place. A missing expected class cannot fall back to creating a new class. Stop requires kernel blocking and queue-purge completion before its durable commit; a missing unsettled kernel slice is an error. Failed changes retain their pending record and attempt selected-client blocking. Kernel ownership or closure uncertainty can quarantine the native plane. These are implementation boundaries; exact debt, counter and revocation behavior still needs real Linux traffic evidence.

Process recovery remains conservative: it closes and accounts surviving leases, retains their charged reservations, and restores the intended policy without restoring an older journal. Full worker restoration must finish before availability. This crash path does not claim live lease adoption or native session continuity. Format3 worker and native credit journals protect the new pending records from format2 readers; incompatible files are preserved and no migration is supplied.

Portable race suites passed for the native controller (8.642 seconds), native configuration/proof helper (1.666), node state (7.182), and release verification (2.881). The expanded authority/expiry/format selector passed in 2.009 seconds, and the real Bolt commit-failure regression passed in 1.482 seconds. A committed expired amendment now accepts exact replay without kernel or reservation work; a genuinely new expired revision is refused. All nine controls in `tools/nodekernel/native-authority-negative.py` reproduced their expected failures, retained in `scratchpad/node-v2/native-authority-negative-rz1_sx0g/`.

The native executable and Linux startup test cross-compiled. Five compatibility cases passed, including a disclosed Windows overlay that executes the actual startup body with only its platform guard bypassed, an old-format2 reader refusing format3 before the backend factory, and removed-format-guard failures. Normal Linux entrypoint and private-namespace installer execution remain pending. The Linux-only runtime-to-controller/authentication-cache fixture is compiled but not executed; neither it nor the portable fault plane substitutes for real daemon/kernel traffic. Latest check details are retained in `scratchpad/node-v2/native-authority-*.log` and `native-format3-*.log`.
