## Implemented foundation

- Explicit blocked, limited, and unlimited forwarding modes; shared per-client upload/download rate admission and combined byte-credit consumption across concurrent connections.
- Monotonic policy revisions, conflicting-replay rejection, expiry, live blocking, and burst preservation when updating a rate. Consumed forwarding authority is intentionally distinct from measured billable usage.
- Xray dispatcher integration using its registered feature mechanism. Both dispatch entry points are wrapped and splice bypass is disabled for governed traffic. This currently proves selected TCP/UDP paths, not every Xray protocol/transport combination.
- An isolated sing-box runtime module using authenticated connection trackers for TUIC and AnyTLS. The master's dependency graph is not upgraded to sing-box's kernel/network dependency versions.
- A versioned protobuf contract and gRPC control/accounting streams, with pinned reproducible generation. Bootstrap enrollment uses a separate HTTPS-only handler; the gRPC listener continues to require mutual TLS.
- A transactional bbolt node store binding node, installation, and control-plane identities; separate received/applied revisions; digest verification and stale-authority rejection; bounded durable accounting spool; cumulative meter validation; and replay/acknowledgment cursors.
- CSR-based short-lived node certificates whose control-plane, node, and installation identities are set by the issuer. Peer identity is read only from a verified TLS 1.3 connection; certificate-request names cannot choose another node's identity.
- Master PostgreSQL reservation and ingestion transactions, explicit grant/meter identity, idempotent operation replay, ordered row locking, batched meter writes, shared parent budgets, and per-installation accounting cursors.
- Master deployment publishing, bounded desired/sent/applied history, controller generations, per-node stream ownership, and independent agent control/accounting loops with reconnect backoff.
- One-time enrollment tickets stored as hashes, CSR public-key binding, stable retry results, revocation checks, and HTTPS-only bootstrap. The node private key is not generated or retained by the master.
- Fleet schema registration and explicit foreign-key migration, including protection against deleting referenced accounting parents.

### Native enforcement implementation checkpoint

`internal/node/native` contains the Linux enforcement driver, a durable credit journal, and an accounting/handover controller. The experimental `penhoon-native` WireGuard runtime now uses it; installer and master-panel integration remain unfinished.

- Each client uses one HTB class per direction on shared IFB devices, across its selected tunnel interfaces. Named nftables quota objects share credit across both directions. Interface/address verdict maps reject unassigned traffic; timed entries and absolute deadline checks enforce authorization expiry in the kernel. Numeric nft time literals use seconds; the absolute deadline is rounded down conservatively, and the integration test reads the installed deadline back from the kernel.
- Tunnel links must have the installation's ownership alias. A new tunnel must be guarded while down, before peers can forward. Existing foreign tables/links and flow offload are refused. Reinitialization repairs the owned base chains without recreating live quota objects. Replay and selector conflicts are checked before changing rate classes.
- Native credit is durably reserved before kernel installation. Retirement blocks the old slice, commits measured counters, marks it finalized, removes its kernel objects and classifiers, then permits a new slice. Uncertain or unused reserved credit is retained conservatively. Missing counters do not turn into a customer charge.
- Native accounting reuses `core.Counter` and `state.CommitCounterUsage`, with one cumulative meter per grant. A 32-refill outage test produces one queued cumulative checkpoint, preserving every measured byte. Journal tests cover missing kernel state, failed usage persistence, a lost delete acknowledgment, revocation, and a new billing term retaining the client's rate-class identity.
- Stream workers and the native controller bind their credit journal's durable identity to the main runtime journal. Replacing or losing only the credit journal now refuses startup. This does not solve coordinated rollback or loss of all node state; those still require the broader recovery workflow.
- Linux race tests pass through two real kernel WireGuard tunnels and through virtual tunnel interfaces. Synchronized clients transferred 2 MiB in each direction in approximately 2.13 seconds under shared 8 Mbit/s directional limits. A separate combined 1 MiB quota stopped both directions below its ceiling. Kernel expiry, installation ownership, replay refusal, and selector conflicts are also exercised.
- Negative compiler overlays make the tests fail when durable reservation is removed, the quota check is removed, the shared rate is doubled, kernel expiry is extended, the deadline uses wrong time units, or journal-replacement detection is removed. These overlays leave implementation files unchanged. Node-package race tests, scoped lint, architecture guards, and the real PostgreSQL control-plane/restart suite pass.

The native candidate still needs adapter integration and qualification before activation. Current boundaries are exact host-address selectors, one node-wide native controller/class allocator, at most 60,000 allocated client classes, a minimum configured limited-rate burst of 64 KiB, and credit slices up to 8 MiB. Class reclamation/sharding, batched control operations, adaptive slice sizing/refill cadence, and load testing remain necessary for fleet-scale operation. The current controller uses nft command transactions and per-grant durable counter commits; no million-client throughput claim is made.

The native measurement layer is accepted inner IP bytes at the firewall gate, including IP/transport overhead. It is not a WireGuard encrypted-byte counter or an application-payload meter. Full burst/packet envelopes, queued packets at revocation/expiry, live rate decreases, IPv6, forwarded/NAT/bridge paths, spoofing isolation, OpenVPN/OpenConnect/AmneziaWG, hostd failure, and every supported OS version remain release gates. Do not add daemon counters on top of these same bytes. The nftables behavior is based on the upstream [stateful-object and timeout contracts](https://netfilter.org/projects/nftables/manpage.html); qualified behavior is limited to the exercised Linux test environment.

### Clock and authority durability follow-through

- Runtime state and credit journals now have separate durable identities. The agent binds both before application; the master refuses replacement journals and unbound funding. Runtime observations separate issued authority, burned reservations, known spendable authority and measured usage. They do not settle billing or reclaim uncertain credit. PostgreSQL/race tests cover identity replacement, report replay, bounded batches and certificate fencing.
- Node expiry now uses an authenticated master-time anchor persisted with the runtime journal and extrapolated using Linux `CLOCK_BOOTTIME`. Wall-clock changes do not extend stream authorization. Same-boot process restarts retain the anchor; a new boot needs a fresh nonce-bound response before forwarding can resume. Responses older than five seconds, repeated responses, foreign identities and failed durable writes cannot establish authority. The entire request round trip is charged to elapsed time, conservatively shortening validity. Clock corruption fails closed and still needs the explicit operator recovery workflow.
- A real TLS/PostgreSQL time-service test rejects superseded node certificates. A worker HTTP test keeps desired configuration unapplied until authenticated time arrives, then restores it without a new deployment. Persistent-governor tests refuse expired authority after restart. Five negative overlays reproduce clock bypass, boot-identity bypass, response replay, premature runtime restore and stale-certificate acceptance. These checks assume the master has correct authoritative UTC and that the host clock can initially validate TLS; they do not establish an independent trusted hardware time source.

## Development commands

- Root foundation: go test ./internal/node/... ./internal/cores/internal/xray/enforcement
- Master integration: PUI_DB_DSN must name the isolated PostgreSQL test database; run go test -race ./internal/controlplane and go test -race -run TestFleetMigrationReferencesPostgres ./internal/database. Without the DSN those tests skip.
- Patched sing-box tests from repository root: go run ./tools/nodecore; -build PATH builds its governed executable.
- Patched MTProto tests from repository root: go run ./tools/nodecore -core mtproto; -race enables Linux race detection and -build PATH builds its governed executable. The private dependency requires the project's normal private-module access; no repository credentials are embedded in the tool.
- Nested runtime lint: go run ./tools/nodecore -lint and go run ./tools/nodecore -core mtproto -lint. The tool prepares a temporary ordinary module with the verified patch, avoiding changes to either dependency cache or checked-in module replacements.
- Native primitive proof on a Linux root test host: unshare --net --mount --propagation private bash tools/nodekernel/probe.sh. The script refuses the initial network/mount namespace and masks /run with private tmpfs before creating its test namespaces.
- Native implementation qualification on a dedicated Linux root test host: bash tools/nodekernel/qualify.sh. This runs journal race tests, private-namespace veth and real WireGuard traffic tests, and negative compiler overlays. It requires nft, tc, ip, wg, Python 3, unshare, and an available WireGuard kernel module. The kernel tests independently refuse the host network/mount namespaces.
- Native runtime integration: bash tools/nodekernel/runtime.sh on the same isolated Linux test host. It runs the actual service/worker path with an unprivileged local caller, real WireGuard traffic, process death/restart and revocation, then repeats with a revocation-bypass compiler overlay that must fail.
- Mixed native runtime: run the same isolated process test with PENHOON_NATIVE_AWG_TEST=1 and PENHOON_NATIVE_RUNTIME_TEST=1; the host must already provide the AmneziaWG module and awg tool.
- Installer verification: bash tools/nodekernel/install-test.sh validates synthetic signed artifacts without installing anything. The filesystem activation/retry test is unshare --mount --propagation private bash tools/nodekernel/install-activation-test.sh; it masks system directories and uses mocked account/service commands.
- Patched sing-box race tests on Linux: go run ./tools/nodecore -race
- Node protocol generation: go run ./tools/nodeproto, using protoc 33.2, protoc-gen-go v1.36.12, and protoc-gen-go-grpc v1.5.1 on PATH; -check verifies freshness without writing.
