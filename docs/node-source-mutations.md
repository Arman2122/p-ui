# Owned source mutation bridge

`SetFleetClientEnabledTx` is an additive, administrator-authorized enable/disable transaction for an immutable owned `FleetClient` ID. It uses an operation receipt and expected client revision, writes the normalized source flag, increments the client and placement revisions, invalidates graph approval, blocks older enabled authority deliveries, cancels outstanding admission demands, and queues per-placement work atomically. It does not change credentials, terms, usage, quota, rates or the current grant pointer.

The writer locks the normalized client, fleet client, and placements. It acquires no node or network-head lock. `FleetSourceWork` deliberately has no target foreign keys, because PostgreSQL's implicit target row locks would invert the node-to-client ordering used by delivery and compilation. Targets are revalidated by the worker. A failed work insertion rolls back the source edit and operation receipt.

`PendingFleetSourceWork` reads at most 128 entries for a node, prioritizes stop work, and rotates pending attempts through a separate availability timestamp. The original enqueue timestamp remains intact. Its revision is independent of the fleet client's lifecycle revision, so a term transition cannot strand a previously committed disable. A later source edit supersedes the desired enable flag but retains the stop requirement and recorded applied-stop revision.

`ProcessFleetSourceWork` requires a root database handle. Its first transaction checks current scope and applied proof, skipping already-converged actions. It releases those locks before a separate callback transaction acquires the node; the callback owns compiler/source lock ordering. After the callback, the worker revalidates the exact work revision, operation and source flag before committing publication and work progress. A superseded action rolls back. Callbacks may publish only database intent, never perform remote effects. An outer transaction is rejected because savepoints would retain the target client locks across both phases.

Callback failures roll back their publication writes, preserve the original error, and defer the exact still-current work for one second through a separate CAS update. `DeferFleetSourceWork` accepts delays from 100 milliseconds to 30 seconds without changing original queue time, stop requirements or pending intent. Superseded work is untouched, so persistent dependency or native funding failures do not monopolize a bounded queue page.

The callback performs stop publication while `RequiresStop` is true. Callback success does not imply an applied stop: every grant for that client, node, installation and runtime must have an exact zero, settled rate and an applied disabled proof. Missing or foreign placement bindings keep the work pending. Existing quota and rate reservations remain intact until their normal acknowledgments settle them.

After stopped authority is proved, a disable can complete. An enable remains pending for fresh source reconciliation and a newer applied publication; it cannot reopen the disabled base configuration. Stream runtimes prove exact applied membership through the indexed admission projection. Native runtimes use a bounded compiled-definition and actual-payload check. The normalized source, current approved placement, identity, credentials and publication must agree before work completes.

Pending stop work also fences direct allocation, refill and enabled authority/credit delivery. Disabled authority remains deliverable against its frozen descriptor. Re-materializing and approving an edited source cannot authorize old credentials: stream delivery checks the exact published placement revision and credential generation, and credit on an auth-only base requires acknowledged enabled authority. Native credit requires the exact compilation provenance and actual enabled baseline grant. A frozen stop publication may carry that original provenance forward; missing provenance fails closed. Refill performs the same scope check before reserving additional quota.

`StopFleetSourceWorkTx` publishes disabled authority for qualified stream runtimes and uses frozen stop configuration for native runtimes. `ReconcileFleetSourceWorkTx` implements the qualified stream enable phase. It locks all normalized node clients in ascending ID order, then logical client IDs, before rematerializing the target and compiling the full node. The durable work authorizes an internal system compilation (`ActorID=0`); public materialization, preview and publication APIs retain administrator authorization. An intervening credential change fails closed. No new term or quota is created. Existing stopped grants enter a newer baseline with blocked rates until fresh authenticated demand restores their shared rates.

Automatic native enable returns an explicit funding requirement. Native convergence requires nonblocked directional rates matching the settled ledger and a fresh report proving positive spendable credit; reserved quota alone is insufficient. Credit-only increases beyond the baseline additionally require the exact current credit acknowledgment on the same applied base, identity and runtime journals. A fresh observation never substitutes for that receipt. Missing or ambiguous publication provenance also refuses native credit. Unresolved full-node compiler dependencies leave work pending.

The compiler can omit a completed disabled source before rejecting its invalidated digest, for both stream and native runtimes. It requires the exact completed disable work, the current normalized disabled flag and immutable logical identity, and a fresh check of every scoped grant's applied stop. Raw disables and unproved stops remain blocked. Publication retains its final grant-retirement check; native address claims remain reserved until the graph omitting them is actually applied.

The existing bulk enable/disable API now resolves owned identities before any inbound mutation and dispatches through the optional transactional `runtime.SourceEnableRuntime` capability. Missing dispatch fails with a typed error before either fleet or nonfleet changes. Each owned target has an administrator-authorized transaction and a partial result; `pending` counts accepted client changes awaiting convergence. Actorless internal legacy callers refuse owned identities. Nonfleet bulk enable updates only its intended normalized flags, rechecks ownership under source locks, and preserves neighboring owned traffic, credentials and attachments. The UI reports pending node confirmation for both single toggles and bulk actions.

Broad client edits, credential/attachment operations and other whole-inbound `SyncInbound` callers still require their own atomic fleet-source routing before full role cutover. The runtime factory remains gated for unsupported commands. The caller must preserve the stated lock order and authorization. Existing reserved authority remains subject to its local limits until the node applies the queued stop. A pending mutation result never promises an immediate remote disconnect.

`RunFleetSourceScheduler` runs with the control host's owned database handle and cancellation lifecycle. It discovers current installations through bounded node keyset pages and processes at most eight due items per node. Obsolete installation work is excluded from the actual work page as well as discovery. Stop publication and enabled-source reconciliation use the same transactional actions above; expected dependency failures defer the exact work without discarding it. Applied proof remains necessary to complete work. A database infrastructure failure propagates to host supervision.

The pending-work index includes node, installation, stop phase, availability and placement. Stop and enable queries constrain that prefix separately, preserving stop priority without scanning another installation's work or future stop attempts. A rolled-back PostgreSQL 16 probe with 100,010 synthetic rows reduced execution buffer access from 708 to 9 for selection of eight due entries; the old plan filtered 50,000 obsolete-installation rows. `tools/nodekernel/source-queue-plan.sql` retains the probe. This measures queue selection, not fleet-wide convergence or traffic capacity.

The initial scheduler uses one worker and a provisional 30-second database deadline per node slice. Whole-node compilation still visits all placements and its pure-Go compilation phase is not cancellable. This bounds database operations, not hard CPU time or fleet-wide convergence latency. Batched compilation, representative large-node measurements and fleet throughput qualification remain required; the scheduler is not evidence of the 1,000-node capacity target.
